# 企业知识问答 Agent：方案设计

版本：1.0；日期：2026-11-09。本文描述当前实现；未实现能力单独标明。

## 1. 技术取舍

Python CLI + 单 Agent 原生循环 + DeepSeek Tool Calls + 本地 JSON 资料。暂不使用 Agent 框架和向量数据库：项目重点在可审计决策、引用和冲突验证，小规模资料可用透明的词法检索完成。模型适配器与执行器分离，之后可替换模型或检索器。

DeepSeek 官方提供由应用执行工具、再回传工具结果的 Tool Calls 接口。拟使用 Chat Completions 接口；API 地址及模型名称通过环境变量配置，具体可用模型在实现时进行最小连接验证，不在代码中假定旧别名永久有效。参考：[Tool Calls](https://api-docs.deepseek.com/guides/tool_calls/)、[Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)。核对日期：2026-11-09。

实际使用 Python 3.9+ 标准库 urllib、json 和 unittest，无第三方运行依赖。CLI 从 .env 加载配置，shell 环境变量优先；真实模型已调用并保存记录。

## 2. 模块职责

| 模块 | 职责 |
|---|---|
| cli | 参数、历史输入、结果打印和退出码 |
| agent | 对话状态、循环、预算、工具分发 |
| model | DeepSeek 请求/响应及离线 Mock 适配 |
| tools | 检索、读取、测试故障注入 |
| retrieval | 资料加载、分词特征、排序 |
| schemas | 输入、工具参数、引用和结果结构 |
| evidence | 已读取证据登记、引用逐字校验 |
| trace | JSONL 事件、脱敏、运行元信息 |
| evaluation | 用例运行、机械断言与评审结果汇总 |

模型负责业务动作与判断；执行器只强制合法参数、证据约束和资源边界。执行器不得硬编码“出现 D02 就返回冲突”或按问题选择答案。

## 3. 工具与结束协议

### search_documents

参数：query（非空）、top_k（默认 5，最大 10）、reason（简短动作目的）。

结果：ok、候选列表。每项含 doc_id、version_date、chunk_id、title、snippet、score；还包含总命中数及是否截断。空列表是成功检索但没有命中，不是异常。

### read_passage

参数：doc_id、chunk_id、reason。

结果：ok、文档 ID、版本日期、片段 ID、完整片段文本、资料指纹。读取成功才登记为可引用证据。错误统一包含 code、message、retryable；例如 NOT_FOUND、TIMEOUT、UNAVAILABLE。

### finish

作为模型提交终态的结构化动作，携带 status、answer、claims、citations、gaps、follow_up_question、reason。claims 将事实性结论映射到引用 ID。

执行器校验结构、引用是否来自本次读取及原文是否逐字匹配；失败则将错误作为观察回传，让模型修正。语义支持性不能仅靠字符串校验保证，必须在评估中逐项审查。合法结束才写入 final.json。

## 4. 决策循环与边界

1. 加载固定资料快照，校验 ID 和版本，记录内容哈希。
2. 将规则、当前问题、可选历史及工具定义发送给模型。
3. 模型选择工具及参数，执行器校验并执行。
4. 保存调用事件，将带调用 ID 的真实结果回传模型。
5. 模型基于观察继续选择动作或提交 finish。
6. 完成引用校验后输出；达到预算则由执行器生成 incomplete。

模型可在歧义明显时直接追问；执行器不强制每个问题都先检索。但 answered 必须携带已经读取的证据。

默认 max_model_turns=12、max_tool_calls=16，所有无效动作和修正轮次也消耗预算；每个实际工具执行前检查余额。同一响应包含多个调用时逐个计数、按顺序执行，不允许批量调用绕过上限。finish 也占动作预算。预算耗尽后不再调用模型来总结，由执行器输出中性的未完成说明和已有证据。

网络请求设置 60 秒超时；对网络、超时、429及5xx最多重试一次；认证、余额及权限错误不重试，脱敏HTTP尝试记录写入 metadata。连续模型错误返回 incomplete，stop_reason=model_error。工具重试由模型根据错误选择，仍受全局预算限制。无效 JSON、未知工具、截断响应不视为成功答案。

## 5. 检索设计与改进证据

基线：原始词法匹配。改进：中文字符二元组、标题及正文特征，加上小规模领域同义词归一化，例如“报账/报销”“最晚/期限”。返回不同文档的候选，避免单份文档多个片段挤占全部结果。分数只表示相关程度，不表示制度权威。

模型仍可根据结果改写查询，例如由“报销期限”补查“适用范围、替代、作废”。同义词表不得包含具体答案，不允许按测试 ID 路由。开发用例和未参与调优的改写用例分开保存。

比较基线与改进的 Recall@5、冲突双方共同召回率和最终答案正确率；同时报告样本量。目标是在小型固定测试集中召回必要证据，不作通用检索能力承诺。

## 6. 冲突策略

模型发现同一事项的不同规定后，读取双方并补查范围、状态及替代关系。日期较新、排名靠前或要求更严格都不是优先依据。

仅在资料明确支持时解释适用差异或替代关系。没有依据时返回 conflict，列出双方原文及缺失的权威关系，并追问适用制度或请求权威确认。对于已有相关候选，不得只读第一份就宣称不存在冲突。

不能假定检索覆盖全库；回答措辞应限定当前证据范围。首版通过小型资料集和冲突召回评估降低遗漏风险，不声称彻底解决。

## 7. 合成资料与测试隔离

拟设计资料：D01 报销期限 30 天；D02 报销期限 15 天且缺范围；D03 报销材料；D04 审批规则；D05/D06 不同差旅类型的材料要求；D07 对 D05/D06 适用范围的说明。

资料按命名快照隔离：clear（不含 D02）、conflict（加入 D02）、scoped（含明确范围依据）、updated（修改有效期限）。不能在所有用例共用的资料里不加区分地同时放入全部相互冲突版本。每次运行固定一个快照，Trace 记录其哈希，防止评估时资料漂移。

故障注入由测试配置指定工具、发生次数和错误码；不写入制度正文，也不提示模型预定结果。分别覆盖一次失败后恢复和持续失败。

## 8. 两类预期路径（不是实际 Trace）

明确答案：检索材料 → 读取 D03 → 已有足够证据 → finish(answered)。

冲突：检索期限 → 读取 D01、D02 → 观察到 30/15 天差异 → 补查适用范围或替代关系 → 未找到解释 → finish(conflict，双方引用及追问)。

真实执行允许动作顺序不同。验收检查依据与行为，不要求模型复刻预设路径。Mock 可以脚本化，用于执行器测试，但必须标记 provider=mock，不计入真实模型路径证明。

## 9. 输出与可复现记录

每次运行保存 examples/archive/早期运行记录/<run_id>/input.json、final.json、trace.jsonl、metadata.json。元信息包含运行模式、模型名称、配置、资料哈希、提示词版本、代码版本（可获取时）、时间及用量（API 提供时）。不持久化密钥或内部推理字段；公开 Trace 仅含动作目的和结果摘要。

真实模型结果可能存在波动，因此关键用例计划重复 3 次，逐次保留失败而非只选择最好结果。机械检查覆盖结构、原文、上限；人工审查覆盖事实支持性、遗漏冲突和追问质量。LLM 自评不能替代事实审查。

实际命令（从仓库根目录执行）：

```sh
PYTHONPATH=src python3 -m enterprise_qa ask --question "报销需要哪些材料？" --dataset data/clear.json --provider deepseek
PYTHONPATH=src python3 -m enterprise_qa ask --input examples/inputs/E12.json --dataset data/rich.json --provider deepseek
PYTHONPATH=src python3 -m unittest discover -s tests -v
PYTHONPATH=src python3 scripts/evaluate_retrieval.py
```

没有 evaluate 子命令。环境变量和各平台配置见 README。工具错误或 incomplete 返回退出码 2，其他业务终态返回 0；配置错误也返回 2。硅基流动是可选适配；DeepSeek 支持 Chat Completions 和 /anthropic 地址对应的 Messages 格式，当前真实验证使用前者。

## 10. 实施顺序与完成条件

1. 资料快照、输入输出契约、检索/读取及工具测试。
2. 执行器、证据校验、预算和 Mock 流程验证。
3. DeepSeek 接入与真实循环，保存两种不同路径。
4. 完整验收矩阵、资料替换、故障注入和检索对照。
5. 补充运行说明、实际评估、AI 使用及复盘文档。

每阶段记录真实耗时。当前已实现核心链路并完成部分真实评估，结果见 03-evaluation.md。后续发布仓库及提交 SHA 时基于真实仓库状态填写。

## 11. 当前实现与设计边界

代码集中在 core.py（执行器、模型、工具、引用校验）、config.py 和 __main__.py；上文模块表是职责划分，不表示每个职责已有独立文件。资料为 data/*.json 快照，片段预先给定。实际文件与说明见 data/README.md，早期 D05/D06/D07 设计由 D10/D11/D12 实现。

Trace 保存工具结果全文，不只摘要；资料均为合成数据。metadata 记录资料哈希、模型及提示词版本标签，包含提示词和源码内容 SHA256、HTTP 尝试；提示词快照保存在批量评估目录。没有 token 用量统计。没有自动语义蕴含判定。使用手写 JSON Schema 子集校验器，验证工具参数类型、必填字段、枚举、嵌套数组与未知顶层参数；不是完整通用 JSON Schema 实现。

已完成核心场景重复3次、12个新增独立问法检索对照及全量回归，具体版本和结果见07-final-validation.md。Mock 仅为执行器脚本，不支持真实语义理解。业务规则不依赖特定文档 ID，但 Mock 的数字冲突启发式不能代表真实模型。
